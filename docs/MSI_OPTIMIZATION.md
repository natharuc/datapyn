# MSI Size Optimization - Implementation Summary

## Problem
The MSI installer generated by CI/CD was exceeding 300 MB, which resulted in:
- Slow distribution and download times
- Excessive storage requirements
- Poor user experience for Windows deployments

## Solution Overview
Implemented comprehensive optimizations across the build pipeline to reduce MSI size:

### 1. PyInstaller Optimizations (`scripts/datapyn.spec`)

#### Excluded Unnecessary Packages
Added extensive exclusions list to prevent bundling of:
- **Test frameworks**: pytest, unittest, doctest and related modules
- **Build tools**: setuptools, pip, wheel, distutils
- **Documentation tools**: sphinx, pydoc
- **Development tools**: IPython, jupyter, notebook
- **Unused stdlib modules**: tkinter, turtle, curses, pydoc_data, test, lib2to3, xmlrpc
- **Unused data science libraries**: scipy, sklearn, statsmodels, seaborn
- **Network protocols**: email, ftplib, telnetlib, poplib, imaplib, smtplib
- **Debugging/profiling**: compiler, pdb, bdb, cProfile, profile, pstats
- **Rare encodings**: Excluded ~40 uncommon character encodings (keeping UTF-8, Latin-1, ASCII)

#### Enabled Binary Stripping
- Set `strip=True` in both EXE and COLLECT to remove debug symbols
- Reduces binary sizes significantly without affecting functionality

#### Optimized UPX Compression
- Enabled UPX compression for most binaries
- Excluded problematic files from UPX:
  - vcruntime*.dll (causes compatibility issues)
  - python*.dll (core runtime)
  - Qt6Core.dll, Qt6Gui.dll, Qt6Widgets.dll (large Qt libraries that don't compress well)

#### Filtered Asset Collection
- Changed from wildcard `*` to specific file extensions
- Only includes necessary asset types: `.ico`, `.svg`, `.png`, `.jpg`
- Automatically excludes documentation files (`.md`, `.txt`, `.rst`)

#### Filtered MariaDB Data
- Applied filtering to mariadb package data
- Excludes documentation, tests, and license files
- Keeps only essential binaries and constants

### 2. WiX Installer Optimizations (`scripts/installer.wxs`)

#### Enhanced Compression
- Added `CompressionLevel="high"` to Package element
- Added `CompressionLevel="high"` to MediaTemplate element
- Uses maximum cabinet file compression

### 3. CI/CD Pipeline Optimizations (`.github/workflows/release.yml`)

#### XSLT Transform for File Filtering
Created `scripts/exclude_docs.xslt` to filter harvested files:
- Removes components with documentation files (.md, .txt, .rst)
- Removes log files
- Removes README, LICENSE, CHANGELOG files
- Removes __pycache__ and .pyc/.pyo files

Applied transform during heat.exe execution:
```powershell
heat.exe dir "$sourceDir" ... -t:scripts\exclude_docs.xslt
```

### 4. Build Artifacts Management (`.gitignore`)

Added patterns to prevent committing build intermediates:
- *.wixobj (WiX object files)
- *.wixpdb (WiX debug databases)
- heat.wxs (auto-generated file list)
- *.msi (installer packages)

## Expected Results

The optimizations target multiple sources of bloat:

1. **Test/Dev Dependencies** (~30-50 MB): Completely excluded from bundle
2. **Documentation Files** (~5-10 MB): Filtered at both PyInstaller and WiX levels
3. **Debug Symbols** (~20-40 MB): Stripped from all binaries
4. **Rare Encodings** (~5-15 MB): Excluded 40+ uncommon character encodings
5. **Better Compression** (~10-20% reduction): High compression in WiX MSI

**Estimated total reduction: 100-150 MB (30-50% size reduction)**

Expected final MSI size: **150-200 MB** (down from 300+ MB)

## Maintenance Notes

### When Adding New Dependencies
- Consider if the package is runtime-required or dev-only
- Add dev-only packages to the excludes list
- Large packages should be evaluated for necessity

### When Adding Assets
- Only add files with extensions in the assets_files list
- Avoid committing large media files if not essential
- Consider compressing images before adding

### Testing Changes
Run PyInstaller locally to test exclusions:
```bash
cd /path/to/datapyn
uv run pyinstaller scripts/datapyn.spec --clean
```

Check dist/DataPyn folder size before and after changes.

## Technical Details

### PyInstaller Excludes Mechanism
- Prevents importing excluded modules at bundle time
- Reduces both code and dependency size
- Safe for truly unused modules
- May cause runtime errors if excluded modules are actually used

### UPX Compression
- Compresses executable binaries
- Runtime decompression is transparent
- Some antivirus software may flag UPX-compressed files
- Excluded DLLs are larger but more compatible

### WiX Transform (XSLT)
- Applied during heat.exe file harvesting
- Removes Component and ComponentRef elements
- Pattern-based filtering on file paths/names
- Processed before candle.exe compilation

## Troubleshooting

### If MSI still too large:
1. Build locally and examine dist/DataPyn contents
2. Use `du -sh dist/DataPyn/*` to find large folders
3. Check for unexpected files in PyInstaller output
4. Verify XSLT transform is being applied (check heat.wxs in build logs)

### If application fails to start:
1. Check for ImportError in logs
2. Module might be incorrectly excluded
3. Remove from excludes list and rebuild
4. Consider using collect_submodules() for problematic packages

### If MSI installation fails:
1. Check WiX build logs for errors
2. Verify all referenced files exist
3. Test installer with verbose logging: `msiexec /i installer.msi /l*v install.log`
